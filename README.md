# Pork Rasher Tray Inspection

Automated visual inspection of packaged pork rashers: **detect and localise packaging defects
in a tray image, then decide whether the tray passes or fails**.

MMA3001 Numerical Methods and Machine Learning, individual project, Monash University, 2026.
Author: Andy Truong.

---

## 1. Engineering problem

Packaged meat trays are currently inspected by eye on the packaging line. Manual inspection is
slow, tiring and inconsistent, and a defective tray that reaches a customer (e.g. an unsealed
pack) is a food-safety and recall risk. This project asks:

> Can a single top-down image of a tray be used to detect and localise packaging defects,
> reliably and fast enough to keep up with a packaging line?

**Scope:** five defect types labelled in the dataset (`loose-meat`, `packaging-error`,
`twisted-meat`, `unsealed`, `wrinkle`). Meat *quality* (e.g. colour) is out of scope because
there are no labels to validate it against.

## 2. Inputs and outputs

| | Description |
|---|---|
| **Input** | One RGB image of a tray, `.jpg/.jpeg/.png/.bmp`, expected 720 × 540 px (W × H), `uint8`. |
| Invalid inputs | Missing file → `FileNotFoundError`. Corrupt file, unsupported type, < 32 px, wrong channels, NaN or out-of-range values → `InvalidImageError`. Greyscale is converted to RGB, RGBA drops alpha, other sizes are resized (flagged). See `porkinspect.io_utils`. |
| **Output 1: detections** | For each defect: bounding box `(x1, y1, x2, y2)` in pixels, class name, confidence in [0, 1]. |
| **Output 2: tray decision** | `PASS`, or `FAIL: <defect types with scores>`. A tray fails if any class score ≥ the decision threshold chosen on the validation set. |

## 3. Method

| | Main model | Baseline |
|---|---|---|
| Model | **YOLOv8n** object detector, COCO-pretrained, fine-tuned (`porkinspect.detector`) | **5-block CNN** trained from scratch, multi-label (`porkinspect.baseline`); design adapted from my ECE4179 Assignment 1 (Q4) |
| Output | Boxes + classes → tray decision | Which defect types are present (no location) |
| Why | Localisation tells the operator *where* the fault is; pretrained features suit a small dataset | Simplest credible alternative: shows whether the extra complexity of detection is justified |

Both models are reduced to the same **tray-level score matrix** (n_trays × 5 classes) so they
are compared on identical metrics.

## 4. Validation

- Predefined Roboflow train / valid / test splits. **The test split is used once**, after all
  choices (epochs, checkpoint, threshold) are fixed on validation.
- **Data audit first** (`porkinspect.data.audit_dataset`): class imbalance, defect-free trays,
  malformed labels, and **leakage** (augmented copies of the same photo in different splits).
- Metrics: detector mAP@0.5 and mAP@0.5:0.95; tray-level per-class precision/recall/F1,
  macro recall (balanced over classes), macro/micro F1, exact-match ratio.
- Sensitivity analysis: decision threshold and input resolution.
- Error investigation: occlusion-sensitivity maps (`porkinspect.occlusion`).

Results are in [`results/`](results/) (generated by the notebook).

## 6. How to run

**Full pipeline (recommended):** open `notebooks/run_pipeline.ipynb` in Google Colab, select a
T4 GPU runtime, set `GITHUB_USER`, and *Run all*. You will be asked for a Roboflow API key
(never stored in the repo).

**Locally:**
```bash
pip install -r requirements.txt
pip install -e .
pytest                                    # run tests
python -m porkinspect.cli tray.jpg --weights results/yolo_best.pt --threshold 0.35
```

**Regenerate docs and test report:**
```bash
pdoc src/porkinspect -o docs --docformat numpy
pytest --html=reports/test_report.html --self-contained-html
```

## 7. Data

training split only), resized to 720 × 540. The data is downloaded by the notebook and is
not stored in this repository.
